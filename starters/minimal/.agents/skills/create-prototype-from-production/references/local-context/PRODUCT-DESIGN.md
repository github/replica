# Product design

> Minimal default context. Replace it through `/setup-skills` when your team has its own guidance.

## Product principles

The current request defines the user, task and scope. Unknown product rules stay unknown rather than invented.

## Prototype fidelity and concept evidence

Match the requested reference or brief except for agreed differences.

## Safe validation scenarios

Prototypes are local and mock-only. Never sign in, submit real data or trigger external side effects to validate them.

## Navigation

Every visible link leads to a built route, an outbound link or an explicit placeholder page.

## Forms and validation

Simulate submissions with local state and deterministic data. Show relevant empty, pending and error states without implying persistence.
