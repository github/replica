# Independent source research

Required for each [document author](./document-authoring.md).
Only the document's complete template defines its research decisions.
Read relevant original sources independently, not another author's notes or
setup's access summary. Scope and authorization come from the immutable registry
and restrictions, including the frozen
[automatic consumer-local scope](./source-workflow.md#automatic-local-repository-research),
not from a reachable page or a generated document. The registry is not an
exhaustive local-file allowlist. An absent repository answer needs no question,
while saved opt-outs and explicit limits still bind every writer.

## Research completion check

The default checkpoint is 12 documentation pages, two link hops or eight
documentation MCP/CLI calls **per complete document**, not a ceiling or per-topic
allowance. At that point compare decisions with evidence. Continue known relevant
authorized detail research for consequential gaps without another permission
question. Do not repeat inventories when existing evidence suffices.

Stop when relevant decisions have sufficient evidence, an explicit exclusion,
actual access restriction, or no applicable guidance after a recorded scoped
search. Honor explicit user/client hard limits, including shared run-wide limits.
Do not multiply a run-wide allowance across authors. Name unattempted leads and
partial decisions honestly. A failed fetch proves failed retrieval, not absent
documentation. A component inventory cannot answer failure/recovery behavior.

## Capture while reading

Record short exact excerpts, conditions, exceptions, recommendation strength,
source URL or exact tool identity and non-sensitive arguments, versions and
destination decisions in your own research directory while the evidence is
present. Preserve website, package, tool and repository version differences.
Recover truncated relevant sections using pagination or exact returned artifacts.
Do not stitch noncontiguous text into a purported exact quote.

Use named public documentation, in-scope consumer-local sources and authorized
read-only documentation tools. For repository-owned decisions, begin with applicable
instructions, README and linked local docs, then optional manifests/scripts and
targeted source/config. Do not assume a package manager or framework. Follow
relevant nested instructions, not a whole-checkout crawl. Discover real tool
schemas before invocation. A skipped application repository is not permission
to use provider code as application
conventions. Missing tool names in an answered service intake are not a skip.
No unrelated private/workplace access, secrets, credentials, private payloads,
authentication, installs or source mutations. Respect content exclusions without
workarounds, keep local reads inside the consumer root without symlinks, and never
run discovered commands except the named design-system CLI's established
read-only operations under [the shared access contract](./source-workflow.md#design-system-cli-access).
Recheck its availability/version and read original evidence independently;
setup's successful access check is not documentation evidence for the writer.
A private consumer checkout is not itself excluded.

## Useful guidance and authority

Write Markdown directly. Explain applicable decisions and usable API/examples,
conditions, exceptions, pending/failure/recovery and keyboard/focus behavior in
the owner root or its applicable directly linked topics, not only research notes.
Keep economical source citations with enough identity/excerpts to check
consequential claims.

Account for the whole template without duplicating "unknown" under every heading.
Distinguish supported guidance, explicit skip, failed access, source conflict,
searched-but-absent guidance and unattempted research. Organizational headings
can refer to covered child decisions. Do not invent a task brief to fill setup
gaps or treat a prototype's current goal/reference as reusable policy.

Provider guidance is not product authority. An observed implementation is not a
required repository rule. Human decisions, documented guidance and bounded
`proposed-default` recommendations remain distinguishable. Only applicable
bounded proposals in the document's template are allowed, retaining their text
and qualifiers. Explicit
topic exclusions prohibit recommendations. Proposals cannot establish permissions,
compliance, persistence, retention or reversibility, even after approval.

## Validator procedures and probes

Document evidenced interfaces, inputs, applicability and fallback separately from
run-specific probes. A declared validator has not necessarily run successfully.
Keep synthetic inputs, diagnostics and failure details in research notes, not
durable policy or global gaps. An unexplained error proves neither universal tool
failure nor a passing check. Validation of actual changed styles is task-time work.

## Local evidence and references

Existing approved local source indexes and byte-preserved snapshots may be
followed during comparison, without claiming fresh verification. New source
captures require storage permission and version/URL/hash provenance. Keep them
in research storage unless explicit activation includes a separate evidence plan.
Main documents must not rely on temporary absolute paths or unactivated notes.
Use stable source IDs, URLs, repository-relative paths with line ranges, and
relative shared-document links. Broken links are unresolved evidence.
